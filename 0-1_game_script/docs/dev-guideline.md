# THE Ultima — 기록문자 및 특수 발화 시스템 개발 지침

현재 개발 중인 THE Ultima의 세계관과 언어 해독 시스템을 다음과 같이 수정하고자 합니다.

**기존 프로젝트의 코드, 스테이지 구성, 데이터 구조를 먼저 확인한 다음 변경 사항을 반영해 주세요.** 기존 기능을 임의로 삭제하거나 전체 구조를 새로 작성하지 마세요.

## 1. 세계관의 기본 설정

게임의 시대적 배경은 약 4100년입니다.

과거 인류는 지구의 다양한 언어를 보존하기 위해 범용 음성 전사 체계를 개발했습니다. 이 기록문자는 여러 언어의 자음과 모음을 표현하고, 한글처럼 음절 단위로 결합하는 구조입니다.

이후 인류 일부가 LHS 행성으로 이주했습니다.

- LHS에서는 공용어와 자동 통역 기술이 확산되면서 지역언어의 사용과 세대 간 전승이 감소했습니다.
- 지구에 남은 사람들은 서로 다른 환경에서 언어를 독자적으로 발전시켰습니다.
- 주인공이 연구하고자하는는 언어는 조지아 스바네티 지역의 언어입니다
  - (소멸된 언어의 특징: 방출음, 복잡한 자음군과 함께 미래에 발달한 휘파람 발화 관습)

주인공은 지구에서 발견한 기록을 해독하는 고고언어학자입니다.

## 2. 범용 기록문자 시스템

기록문자는 독립적인 자연언어가 아니라 여러 언어의 발음을 기록하기 위한 인공 표기 체계입니다.

### 문자 구성

- 기본 단위: 자음, 모음, 발음 보조 부호
- 기본 구조: 자음 + 모음(CV)
- 확장 구조: V, VC, CVC, CCV, CCVC 등
- 음절 단위로 글자를 하나의 사각형 블록 안에 결합
- 기본적으로 왼쪽에서 오른쪽으로 기록

### 자음

자음은 조음 위치, 조음 방법, 추가 발음 특성으로 구분합니다.

예시:

- /k/: 무성 연구개 파열음
- /ɡ/: 유성 연구개 파열음
- /kʰ/: 유기음
- /kʼ/: 방출음

유사한 발음은 유사한 기본 글자 형태를 공유하며, 보조 부호로 구별합니다.

### 모음

모음은 기본 음색에 비음화와 장단 부호를 추가하는 방식으로 구성합니다.

예시:

- /a/: 기본 모음
- /ã/: 비음화 모음
- /aː/: 장모음
- /ãː/: 비음화 장모음

예를 들어 /kʼãː/는 방출 자음과 비음화 장모음을 결합한 하나의 음절 블록입니다.

**아직 최종 문자 모양과 전체 음소 목록은 확정되지 않았습니다.** 현 단계에서 임의로 새로운 문자나 음소 목록을 완성하지 마세요. 확장 가능한 데이터 구조를 우선 설계합니다.

## 3. 기록문자의 역사적 변화

범용 기록문자는 인류 이주 이전에 개발되었습니다.

이후 LHS에서는 일부 발음 구별과 기록 기호의 사용이 줄어들었습니다.

반면 지구에서는 언어가 독자적으로 변화하면서 LHS에서 사용되지 않는 발음과 문자 조합이 유지되거나 새롭게 나타났습니다.

주인공은 지구에서 발견한 기록을 통해 잊힌 발음 구별과 문자 조합을 복원합니다.

여기서 다음 두 개념을 구별해야 합니다.

1. 기록문자를 읽을 수 있다는 것: 글자에 대응하는 발음을 어느 정도 추정할 수 있음
2. 언어를 이해한다는 것: 단어의 의미와 문법을 해독할 수 있음

기록문자를 읽는다고 해서 지구의 소멸 언어를 자동으로 번역할 수 있는 것은 아닙니다.

## 4. 특수 발화 표기법 — 주인공의 새로운 연구 성과

**가장 중요한 변경 사항입니다.**

기존 범용 기록문자는 일반적인 자음, 모음, 성조, 방출음 등을 표현할 수 있지만, 휘파람처럼 특수한 발화 방식의 시간적·음향적 특성을 충분히 기록하지는 못합니다.

게임 후반부에서 주인공은 이러한 한계를 발견하고, 범용 기록문자를 보완할 새로운 전사 표기법을 고안합니다.

### 특수 발화 기호 (임시안)

| 기호 | 의미        |
| -- | --------- |
| ↗  | 음높이 상승    |
| ↘  | 음높이 하강    |
| →  | 음높이 유지    |
| ∿  | 음높이 반복 변동 |
| —  | 소리 지속     |
| ‖  | 발화 단절     |

이 기호들은 최종 그래픽이 아니라 기능 정의를 위한 임시 표기입니다.

주인공이 새롭게 발명하는 것은 휘파람 발화 자체가 아니라, **과거의 발화 흔적을 분석하고 기록하기 위한 체계적인 전사 방법**입니다.

또한 원본 음성이 없다면 실제 발음을 완벽하게 복원할 수 없습니다. 게임에서도 이 한계를 유지합니다.

## 5. 개발 구조

기록문자 시스템은 데이터 중심으로 설계해 주세요.

최소한 다음 개념을 분리합니다.

- `Phoneme`: 자음 또는 모음과 IPA 정보
- `PhoneticFeature`: 조음 위치, 조음 방법, 비음화, 길이 등
- `Grapheme`: 발음을 표현하는 기본 문자 기호
- `SyllableBlock`: 음절 단위로 결합한 문자 구조
- `Diacritic`: 발음 특성을 나타내는 보조 부호
- `SpecialVocalization`: 휘파람 등 특수 발화 유형
- `TranscriptionHypothesis`: 주인공이 제시한 해독 가설
- `DeciphermentProgress`: 플레이어가 발견하거나 확정한 해독 규칙

### 개발 시 유의 사항

1. IPA 표기와 실제 게임 문자 그래픽을 분리합니다.
2. 하나의 음절에 여러 자음이 결합할 수 있도록 설계합니다.
3. 문자 기호는 나중에 이미지·SVG·폰트 등으로 교체할 수 있도록 합니다.
4. 특수 발화 기호는 초반부터 사용할 수 없고, 스토리 진행에 따라 해금합니다.
5. 플레이어의 해독 가설과 실제 정답 데이터를 구분합니다.
6. 기존 언어 퍼즐 및 스토리 데이터를 최대한 재사용합니다.
7. 언어의 표기 규칙과 단어의 의미 해독 규칙은 독립적으로 관리합니다.

## 7. 현재 작업 요청

우선 다음 작업을 진행해 주세요.

1. 기존 프로젝트의 언어 및 문자 시스템 구현 구조를 분석합니다.
2. 위 설정과 충돌하는 부분을 찾습니다.
3. 범용 기록문자를 위한 데이터 모델 및 음절 결합 로직을 설계합니다.
4. 특수 발화 표기법을 향후 추가할 수 있는 확장 구조를 마련합니다.
5. 기존 스토리 및 스테이지 데이터에서 변경이 필요한 부분을 정리합니다.
6. 확정된 규칙만 구현하고, 미확정 문자 디자인은 임시 데이터로 구분합니다.
