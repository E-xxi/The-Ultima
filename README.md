## 실행과 점검

```sh
cd game
python3 -m http.server 8000     # 브라우저에서 http://localhost:8000
npm test                         # 자동 점검 (Node 18 이상)
```

- **테스트 모드:** 주소 끝에 `#test`를 붙여 열면(예: `http://localhost:8000/#test`, 아티팩트 링크 뒤 `#test`) 시작 지점 목록이 떠요. 0단계 각 방, 1단계 기지 도착·도서관 입구·보고서 직전에서 바로 시작할 수 있어요.
- **테스트 중 저장:** 테스트 중에는 진짜 저장을 건드리지 않아요. 시작 지점은 개발용 `data/dev.json`에 있고, 출시 빌드에서는 이 파일을 빼요.

- **로컬 서버 필요:** `index.html`을 파일로 바로 열면 `data/*.json`을 불러오지 못해요. 위 명령처럼 로컬 서버로 여세요.
- **빌드와 라이브러리 없음:** 그림은 모두 코드로 찍는 픽셀이에요(이미지 파일 없음).
- **폰트:** Google Fonts의 Gowun Batang, Nanum Pen Script.

## 폴더 구조

```
game/
  index.html          화면 틀과 스타일
  data/               게임 내용 (코드를 고치지 않고 여기만 고쳐서 늘린다)
    language.json     두 문자 체계: 기계 표기 조각, 화자 문자 형태소(모양·소리·뜻 = 정답)
    records.json      해독 대상: 기록 꾸러미, 단어 모음집, 표
    story.json        대사, 꺼내 읽는 문서, 단계 카드, 화면 문구
    maps.json         장소(타일·물건·시작점), 문과 잠김 조건, 시작 장소
    puzzles.json      퍼즐: 선행 조건, 정답 데이터, 풀린 뒤 효과
    dev.json          개발용 테스트 시작 지점 (#test). 출시 빌드에서 뺀다
  src/
    main.js           전체를 잇는 곳: 불러오기 → 검증 → 저장 읽기 → 입력·이동·효과·자동 저장 → 그리기
    state.js          진행 상태와 그 상태를 바꾸는 함수, 조건 판정
    story.js          대사 변형 고르기, 효과 실행
    puzzles.js        퍼즐 유형별 판정 (유형마다 함수 하나)
    save.js           저장·불러오기·버전 변환·검증
    data.js           데이터 불러오기와 검증 (중복 id, 없는 참조, 잘못된 조건)
    language.js       문자 데이터를 쓰기 쉽게
    world.js          맵 모델, 충돌, 조사 대상 찾기
    render.js         지형·물건·조명·확대 화면 그리기
    art.js            픽셀 그림 (타일, 사람, 물건, 사진, 기록 면)
    ui.js             대화창, 노트, 문서, 퍼즐 화면, 시작·끝 화면
  tests/
    run.js            데이터·저장·퍼즐·진행 순서·맵 도달 점검
    smoke.js          가짜 DOM으로 게임을 띄워 보는 연기 점검
```

**의존 방향:** `main` → `ui`, `render`, `world`, `story`, `puzzles`, `save`, `data`. 순수 모듈(`state`, `story`, `puzzles`, `save`, `data`, `world`, `language`)은 DOM을 쓰지 않아서 Node에서 바로 점검해요.

## 데이터 규칙

- **고유 id:** 모든 대사, 문서, 기록, 퍼즐, 맵, 물건, 문에 바뀌지 않는 id를 둬요. 불러올 때 중복과 없는 참조를 검사하고, 문제가 있으면 게임 대신 오류 목록을 띄워요.
- **조건:** `종류:id` 문자열 또는 그 배열(모두 참)이에요. 앞에 `!`를 붙이면 부정이에요. 종류는 `event`(일어난 사건), `read`(읽은 문서), `seen`(본 기록), `solved`(푼 퍼즐), `visited`(가 본 장소)예요.
- **효과:** `event:id`, `chapter:N`, `goto:맵/시작점`, `card:id`, `open_read:id`, `open_puzzle:id`, `chapter_end:N`.
- **대사:** 변형 목록 중 조건이 맞는 첫 번째를 써요. 한 줄은 `[말하는 사람, 방식, 문장]`이고, 방식은 `direct`(가족, 중계기 끔) / `relay`(그 밖의 사람) / `thought`(혼잣말)예요.
- **물건의 `use`:** `dialogue:id` / `read:id` / `inspect:id` / `door:id`.
- **받은 아이템(`story.json` `items`):** `{id, label, icon, when, use, key}`. `when` 조건이 맞으면 왼쪽 위 아이템 칸에 나타나고, 누르거나 `key`(예: `KeyR`)를 누르면 `use`(지금은 `read:id`)를 실행해요. 새 아이템은 여기에 한 줄 추가하면 돼요.
- **정답과 추측 분리:** 뜻(정답)은 `language.json`에만 있어요. 플레이어의 추측(노트, 글자별 추측 낱말 `guesses`, 보고서 해석)은 저장 상태에만 있어요.

**새 내용 추가 예:**
- 대사 하나: `story.json`의 `dialogues`에 추가하고, 물건의 `use`에 연결해요.
- 기록 하나: `records.json`에 추가하고, `maps.json`에 `inspect:` 물건을 둬요.
- 새 퍼즐 유형: `puzzles.js`에 판정 함수 하나, `main.js`에 화면 연결 하나를 더해요.

## 저장

| 항목 | 값 |
| --- | --- |
| 위치 | 브라우저 `localStorage`의 `ultima.save` (막혀 있으면 메모리에만 두고 한 번 알림) |
| 형식 | `{save_version, game_version, saved_at, state}`. 지금 `save_version`은 2 (v1 → v2: 글자별 추측 `guesses` 추가) |
| 쓰는 때 | 장소를 옮길 때, 사건·문서·퍼즐로 상태가 바뀔 때, 노트를 고칠 때(0.4초 모아서) |
| 끊김 대비 | 임시 키(`ultima.save.tmp`)에 먼저 쓰고 본 키로 옮겨요. 본 키가 망가졌으면 임시 키를 읽어요 |
| 읽을 때 | 형식을 검증하고, 오래된 버전은 차례로 변환해요(v0 = 저장 기능 전 시안). 더 새로운 버전은 거부해요 |
| 시작 화면 | 저장이 있으면 이어하기 / 처음부터(한 번 더 눌러 확인) |

- **아직 없는 것:** 그래픽·사운드 같은 기기별 설정이 아직 없어요. 생기면 진행도와 다른 키에 저장해요.
- **Steam Cloud:** 엔진을 정한 뒤 같은 저장 형식을 파일로 쓰는 방식으로 붙여요.

## 화면과 조작

| 항목 | 값 |
| --- | --- |
| 타일 | 16×16px |
| 내부 해상도 | 긴 변 ≈ 480px. `SCALE = max(2, round(긴 변 / 480))` 정수배 확대 |
| 플레이어 | 16×22px, 4방향 × 걷기 3프레임, 60px/s, 발 상자 8×4px |
| 조사 | 바라보는 방향 10px 앞 지점에서 8px 이내. 조사할 수 있는 것 앞에만 `!` |
| 노트 | 화면 오른쪽 세로 판(위 15%~아래 12%, 폭 최대 340px). 맨 위 네모 5개가 1~5장. 펼친 채로 걷고 조사할 수 있고, 게임·확대 화면은 노트 왼쪽 영역에 맞춤. 칸을 누르면 그 글자에 추측 낱말(10글자)을 적거나 칸을 지움. 폭 760px 미만 화면에서는 아래쪽에 붙음 |
| 버튼 | 노트 버튼은 오른쪽 아래. 받은 아이템(지금은 사전 기록지)은 왼쪽 위에 차례로 놓임 |

| 키 | 동작 |
| --- | --- |
| 방향키 / WASD | 이동 (확대 화면 + 노트일 때는 글자 고르기) |
| E / Space / Enter | 조사, 대사 넘기기, 확대 화면에서 글자 옮겨 적기 |
| Q | 노트 (지도교수에게 받은 뒤) |
| R | 사전 기록지 (지도교수에게 받은 뒤. `items`의 `key`로 정함) |
| Esc | 노트 → 문서 → 확대 화면 순으로 닫기 |

**창 포커스:** 창이 포커스를 잃으면 눌린 키를 놓아요. 터치 화면에서는 방향 패드와 `!` 버튼이 나와요.

## 문자 체계와 정답표

- **기계 고유 표기:** 한글처럼 모아 쓰는 소리글자예요. 첫소리 조각 9개, 가운데소리 조각 6개(세로는 오른쪽, 가로는 아래)이고, 기록 띠에는 띄어쓰기가 없어요.
- **화자의 문자:** 한 기호가 한 형태소예요. 왼쪽에서 오른쪽으로 읽고, 동물은 오른쪽을 봐요. 표지가 띄어쓰기이고, 합성어와 어미는 붙여 써요.
- **정답표:** 정답(스포일러)은 `game/data/language.json`의 `morphemes`(뜻·소리)와 `records.json`(기록별 문장)에 있어요.

## 연출 원칙

- 게임 화면은 브라우저 화면을 꽉 채우고, 따로 게임 설명을 띄우지 않아요. 배경은 방 안의 물건(일기장, 역사서 등)으로 전해요.
- 기호 뜻에 대한 힌트는 주지 않아요. 플레이어는 노트에 직접 가설을 적어요.
- `!`에서 조사하면 기록이 화면 가득 확대되고, 바깥을 누르면 지형으로 돌아가요.
- 유물과 가구는 지나갈 수 없어요.
